# Security model

Imported projects and tested targets are untrusted. The platform itself is a single-owner local tool.

## Trust boundaries

| Zone | Trust | Examples |
|---|---|---|
| Host processes | trusted | API, worker, dashboard, Ollama |
| Trusted tools on untrusted data | medium | Trivy, Semgrep (containers, source mounted read-only) |
| Untrusted code | none | Imported project tests, dependency install scripts, AI-generated patches |
| Untrusted content | none | Pages and API responses of tested targets, uploaded archives |

## Access to the platform

- API and dashboard bind to `127.0.0.1`. `QAI_API_HOST` other than localhost is rejected by `scripts/validate-env.ps1`.
- Every `/api` route requires the bearer token from `.env` (constant-time comparison). `/health` returns liveness only.
- `TrustedHostMiddleware` (API) and a host check (dashboard proxy) reject unknown `Host` headers (DNS rebinding).
- The dashboard proxy rejects state-changing requests whose `Origin` is not the dashboard itself (CSRF) and forwards only plain path segments.
- The token never reaches the browser. Secrets live only in `.env` (git-ignored, generated by `scripts/setup-env.ps1`). Provider API keys are read from the environment and never stored in the database.
- Errors: clients receive `internal server error`; details go to the structured log only.

## Importing content (`app/security/archive.py`)

- ZIP: rejects absolute paths, `..`, drive letters, Windows reserved names, symlinks and encrypted entries; enforces total size, per-file size, file count and a compression-ratio limit measured on real bytes while streaming.
- Local folders: copied without following symlinks; the original is never modified.
- Secret-like files (`.env*`, `*.pem`, `*.key`, SSH keys, `.npmrc`, ...) are **not copied**; only their names are recorded.
- Uploads are size-capped while streaming and deleted after import.
- Nothing is executed during import or discovery (parsing only: JSON, TOML, YAML `safe_load`, regular expressions).

## Sandbox for untrusted code (`app/engines/sandbox.py`)

Every container is started with: `--cap-drop ALL`, `--security-opt no-new-privileges`, `--read-only`
root filesystem, size-limited `tmpfs /tmp`, `--cpus`, `--memory` (= `--memory-swap`, so no swap),
`--pids-limit`, a wall-clock timeout followed by `docker kill`, a non-root user (`10001`), and only
explicitly listed mounts. No host environment variables, credentials or Docker socket are passed.

Project tests run in three steps on a throw-away volume: copy the workspace (trusted `cp`/`chown`
only, no network), install dependencies (**network enabled**), run tests (**network disabled**). The
volume is removed afterwards. The stored project version is mounted read-only and never changes.

## Outbound requests (`app/security/ssrf.py`)

- Only `http`/`https`; URLs with credentials are rejected.
- A target must be on the owner's allowlist (`host:port`) before any plan or run is accepted, and again at request time.
- Hostnames are resolved and every address checked. Private, loopback and link-local addresses need an explicit allowlist entry.
- Cloud metadata addresses (169.254.169.254, fd00:ec2::254, ..., including IPv4-mapped IPv6 forms) are blocked even when allowlisted.
- Redirects are followed manually and re-validated on every hop (maximum 5).
- Browser: every request is intercepted. Navigations must be authorised targets; subresources may load from public addresses only.
- API checks are capped per check; latency sampling is sequential. No load or fuzz testing exists.
- State-changing API calls are skipped unless the owner enables them per plan.

## Repair safety

- No patch is applied without an explicit decision; decisions are audited.
- Patches touching auth/payment/crypto/session-like paths need an additional explicit confirmation.
- Patches are applied to an isolated copy on a git branch (git run with system/global config and hooks disabled).
- Binding policy review: only declared files changed, no test file modified, nothing deleted, no secret-like file, bounded size.
- AI can propose and comment. It cannot approve, verify or change a result state.
- AI patch paths are restricted by JSON schema to the source files that were shown to the model.

## Paid AI

Disabled by default. A paid call requires all of: provider enabled, explicit approval timestamp, API
key present, prices entered, monthly and per-project budget not exceeded by a pessimistic estimate.
The check runs at routing time and again immediately before the call. Every call is recorded in `ai_usage`.

## Residual risks (accepted for the MVP)

| Risk | Why it remains | Mitigation / recommendation |
|---|---|---|
| Container escape | Docker shares the host kernel; it is not a hard security boundary | Do not run projects you consider hostile. Use a dedicated VM for high-risk code |
| Network egress during dependency install | Package installs need the network; the default bridge can reach the internet and possibly the LAN | Install runs non-root with no capabilities and a timeout. An egress proxy/allowlist is the next hardening step |
| No disk quota on sandbox volumes | Docker Desktop volumes do not support per-volume quotas | Timeouts and removal after each job bound the damage; watch free disk (System Health) |
| DNS rebinding between check and connection (TOCTOU) | The HTTP client and browser resolve again when connecting | Allowlist is exact `host:port`; prefer IP literals for local targets |
| Browser runs on the host | See ADR-006 | Chromium's own sandbox; downloads and service workers disabled; move to a container later |
| No rate limiting or multi-user authorization | Single local owner | Never expose ports 3000/8000 to a network |
| Scanners need the network | Vulnerability DB and rule downloads | Containers are capability-less with read-only source; Semgrep metrics are off |
| Evidence may contain sensitive response data | HTTP exchanges are stored (first 4 KB) | `data/` and `backups/` are git-ignored; treat them as confidential |
